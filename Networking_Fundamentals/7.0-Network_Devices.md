# Network Devices

## Learning Objectives

By the end of this lesson, students will be able to:

- Identify common network devices used in enterprise environments.
- Explain the purpose of routers, switches, firewalls, load balancers, and proxy servers.
- Understand how network devices support application communication.
- Recognize common production incidents involving network devices.
- Apply knowledge of network devices during troubleshooting.
- Understand which teams typically manage various network components.

---

# Introduction

Modern applications depend on many network devices working together to deliver services to users.

When a user accesses an application, their request often travels through multiple network devices before reaching its destination.

Example:

```text
User
  |
  v
Router
  |
  v
Firewall
  |
  v
Load Balancer
  |
  v
Web Server
  |
  v
Application Server
  |
  v
Database Server
```

If any device in this path fails or is misconfigured, users may experience:

- Slow performance
- Connection errors
- Intermittent failures
- Complete outages

For Production Support professionals, understanding the role of each network device helps identify where communication problems may occur.

Many application incidents involve infrastructure components rather than application code.

- Proxy misconfigurations

When Production Support analysts understand how network devices operate, they can:

- Ask better troubleshooting questions
- Gather useful diagnostic information
- Escalate incidents appropriately
- Reduce incident resolution times

# Router

## What Is a Router?

A router connects different networks and determines the best path for data to travel.

Think of a router as a GPS system for network traffic.

Its job is to determine:

```text
Where should this data go next?
```

---

## Router Example

```text
Office Network
      |
      v
    Router
      |
      v
Data Center Network
```

The router directs traffic between networks.

---

## Responsibilities

- Forward data between networks
- Select the best route
- Maintain routing tables
- Connect internal networks to external networks

---

## Common Production Issues

### Routing Failure

Symptoms:

```text
Server unreachable
```

### Incorrect Route

Symptoms:

```text
Traffic sent to wrong destination
```

### Network Outage

Symptoms:

```text
Multiple applications unavailable
```

---

## Support Questions

- Can the destination network be reached?
- Has a routing change occurred?
- Are other systems affected?

---

# Switch

## What Is a Switch?

A switch connects devices within the same network.

Unlike a router, which connects different networks, a switch enables communication within a network segment.

---

## Switch Example

```text
                Switch
               /  |  \
              /   |   \
             /    |    \
      Server1 Server2 Server3
```

All devices communicate through the switch.

---

## Responsibilities

- Connect local devices
- Forward data within a network
- Improve network efficiency
- Manage traffic using MAC addresses

---

## Common Production Issues

### Switch Failure

Symptoms:

```text
Servers lose connectivity
```

### Port Failure

Symptoms:

```text
Single device unavailable
```

### VLAN Configuration Issues

Symptoms:

```text
Device can communicate with some systems
But not others
```

---

## Support Questions

- Are multiple systems affected?
- Is the network interface active?
- Did recent network changes occur?

---

# Firewall

## What Is a Firewall?

A firewall controls network traffic entering and leaving a system.

Its primary purpose is security.

Firewalls determine:

```text
Allow Traffic
```

or

```text
Block Traffic
```

based on predefined rules.

---

## Firewall Example

```text
Application Server
       |
   Firewall
       |
Database Server
```

The firewall decides whether communication is allowed.

---

## Responsibilities

- Filter traffic
- Enforce security policies
- Prevent unauthorized access
- Control communication between systems

---

## Common Production Issues

### Blocked Port

Symptoms:

```text
Connection Timeout
```

Example:

```text
Database Port 1433 Blocked
```

---

### Missing Firewall Rule

Symptoms:

```text
New Application Not Accessible
```

---

### Incorrect Security Policy

Symptoms:

```text
Intermittent Connectivity Failures
```

---

## Support Questions

- Is the required port open?
- Was a firewall change recently implemented?
- Can other systems access the destination?

# Load Balancer

## What Is a Load Balancer?

A load balancer distributes traffic among multiple servers.

Instead of sending all requests to a single server, requests are spread across multiple servers.

---

## Load Balancer Example

```text
                     Load Balancer
                    /      |      \
                   /       |       \
                  /        |        \
          Server 1   Server 2   Server 3
```

Traffic is distributed across all available servers.

---

## Benefits

- Improved availability
- Increased scalability
- Better performance
- Reduced server overload

---

## Health Checks

Load balancers perform health checks to verify server availability.

Example:

```text
Server 1 = Healthy
Server 2 = Healthy
Server 3 = Unhealthy
```

Traffic is automatically redirected away from unhealthy servers.

---

## Common Production Issues

### Failed Health Checks

Symptoms:

```text
Application unavailable
```

---

### Incorrect Routing

Symptoms:

```text
Users receive unexpected errors
```

---

### Session Persistence Issues

Symptoms:

```text
Users randomly logged out
```

---

## Support Questions

- Are all backend servers healthy?
- Are health checks passing?
- Is traffic reaching the correct server?

---

# Production Support Case Study

## Incident

Users report that a web application is unavailable.

---

## Investigation

DNS:

```text
Working
```

Application Service:

```text
Running
```

Database:

```text
Healthy
```

Load Balancer Health Check:

```text
Failed
```

---

## Root Cause

The load balancer incorrectly marked all application servers as unhealthy.

No traffic was forwarded to backend servers.

---

## Resolution

Health check configuration corrected.

Traffic distribution resumed.

Application restored.

---

## Lesson Learned

Application outages are not always caused by application failures.

Infrastructure devices often play a critical role in service availability.

# Production Support Troubleshooting Workflow

When users report an application outage, follow a structured approach.

### Step 1: Confirm the User Impact

Questions:

```text
Can all users reproduce the issue?
Does it affect one location or many?
Did the issue begin suddenly?
```

---

### Step 2: Verify Application Health

Check:

```text
Application Status
Server Status
Database Status
```

---

### Step 3: Review the Network Path

Example:

```text
User
 |
Router
 |
Firewall
 |
Load Balancer
 |
Application
```

Determine where communication fails.

---

### Step 4: Validate Device Status

Questions:

```text
Are firewall rules intact?
Are load balancer health checks passing?
Can traffic reach the destination?
```

---

### Step 5: Escalate with Evidence

Provide:

```text
Error Messages
Affected Servers
Network Test Results
Relevant Logs
```

This speeds resolution by reducing unnecessary investigation.

# Production Support Case Study

## Incident

Users report that the Human Resources portal is unavailable.

The application URL is:

```text
https://hr.company.com
```

---

## Investigation

### DNS Lookup

```text
Successful
```

---

### Ping Test

```text
Successful
```

---

### HTTPS Connectivity

```text
Failed
```

---

### Load Balancer Review

```text
No Healthy Backend Servers
```

---

### Application Server Status

```text
Healthy
```

---

## Root Cause

A recent update changed the load balancer health check URL.

The load balancer incorrectly identified all backend servers as unhealthy.

No traffic was routed to the application.

---

## Resolution

Health check configuration corrected.

Backend servers marked healthy.

Traffic resumed normally.

---

## Lesson Learned

The application itself was not the problem.

The outage occurred because the load balancer prevented traffic from reaching healthy application servers.

- High availability
- Improved performance
- Fault tolerance
- Scalability

---

## What happens if a firewall blocks a required port?

Communication fails between systems even if both systems are functioning correctly.

Example:

```text
Application -> Database
```

Port blocked:

```text

```

A proxy server acts as an intermediary between clients and destination systems.

# Summary

Network devices form the foundation of enterprise application communication. Routers, switches, firewalls, load balancers, proxy servers, and other infrastructure components work together to ensure applications are accessible, secure, and highly available.

Production Support professionals do not need to become network engineers, but they must understand how these devices function and how failures can impact applications. This knowledge enables faster troubleshooting, more accurate root cause identification, and better collaboration with infrastructure teams during incident response.
