# Introduction

The Domain Name System (DNS) is often referred to as the **phonebook of the Internet**.

Humans prefer using names like:

```text
www.google.com
orders.company.com
api.company.com
```

Computers communicate using IP addresses such as:

```text
142.250.190.78
10.100.5.25
```

DNS serves as the translation service that converts human-readable hostnames into machine-readable IP addresses.

Without DNS, users would have to remember IP addresses for every application they use.

DNS is one of the most important networking concepts for Production Support professionals because DNS failures often appear to users as application outages.

---

# What Is DNS?

DNS stands for **Domain Name System**.

Its primary function is to translate domain names into IP addresses.

Example:

```text
orders.company.com
```

might resolve to:

```text
10.25.30.50
```

Applications rely on DNS to locate services, databases, APIs, and servers.

Without DNS, computer systems would be unable to find one another efficiently.

---

# Why DNS Matters in Production Support

DNS plays a critical role in application communication.

Production Support teams frequently investigate incidents involving:

- Applications that cannot locate backend services
- Failed API calls
- Unreachable websites
- Database connection failures
- Delayed service availability after deployments

Many incidents that appear to be application failures are actually DNS issues.

Example:

```text
User cannot access application.
```

The application may be functioning correctly, but DNS is failing to resolve the application's hostname.

# Hostnames vs IP Addresses

## Hostname

A hostname is a human-friendly name assigned to a device or service.

Examples:

```text
orders.company.com
api.company.com
db.company.com
```

---

## IP Address

An IP address is the numerical address used for network communication.

Examples:

```text
10.20.30.40
192.168.1.100
```

---

## Relationship

```text
orders.company.com
        |
        v
    DNS Lookup
        |
        v
10.20.30.40
```

DNS creates the relationship between hostnames and IP addresses.

---

# DNS Hierarchy

DNS is organized into a hierarchical structure.

Example:

```text
orders.company.com
```

Breakdown:

```text
.com       = Top-Level Domain (TLD)
company    = Domain
orders     = Hostname
```

Visual representation:

```text
Root
 |
 +-- .com
      |
      +-- company
            |
            +-- orders
```

This hierarchy enables DNS servers worldwide to locate and resolve names efficiently.

# DNS Lookup Process

When a user enters:

```text
https://orders.company.com
```

DNS performs a lookup to determine the correct IP address.

### Step 1

User requests:

```text
orders.company.com
```

### Step 2

Operating system checks local DNS cache.

### Step 3

If not found, request is sent to a DNS server.

### Step 4

DNS server searches for a matching record.

### Step 5

IP address is returned.

Example:

```text
orders.company.com
     ->
10.25.30.50
```

### Step 6

Browser connects to the server using the returned IP address.

# Internal DNS vs External DNS

Organizations typically use both internal and external DNS.

---

## External DNS

Used for publicly available services.

Examples:

```text
www.company.com
shop.company.com
support.company.com
```

Accessible from:

- Home networks
- Mobile devices
- Internet users

---

## Internal DNS

Used within an organization's network.

Examples:

```text
app-dev.company.local
db-prod.company.local
api-internal.company.local
```

Accessible only to internal users and systems.

# Common DNS Record Types

DNS records store information about domains and services.

Production Support analysts should understand the most common record types.

---

# A Record

Maps a hostname to an IPv4 address.

Example:

```text
orders.company.com
       |
       v
10.25.30.50
```

---

# AAAA Record

Maps a hostname to an IPv6 address.

Example:

```text
app.company.com
       |
       v
2001:db8::1234
```

---

# CNAME Record

Creates an alias for another hostname.

Example:

```text
portal.company.com
         |
         v
web.company.com
```

Benefits:

- Easier maintenance
- Simplified hostname management

---

# MX Record

Specifies mail servers responsible for email delivery.

Example:

```text
company.com
      |
      v
mail.company.com
```

Used by:

- Outlook
- Exchange
- Email gateways

---

# TXT Record

Stores text-based information.

Often used for:

- Email validation
- Domain ownership verification
- Security policies

Examples:

```text
SPF
DKIM
DMARC
```

---

# PTR Record

Provides reverse DNS lookups.

Example:

```text
10.20.30.40
      |
      v
server01.company.com
```

Useful in:

- Security investigations
- Log analysis
- Monitoring systems

---

# DNS Caching

DNS responses are often cached to improve performance.

Benefits:

- Faster lookups
- Reduced DNS traffic
- Improved user experience

Example:

```text
orders.company.com
```

After the first lookup, the result may be stored locally.

Subsequent requests can use the cached result instead of querying DNS again.

---

# Time To Live (TTL)

TTL determines how long a DNS record remains cached.

Example:

```text
TTL = 3600
```

Meaning:

```text
1 hour
```

Higher TTL values:

- Reduce DNS traffic
- Slow propagation of changes

Lower TTL values:

- Allow faster updates
- Increase DNS query volume

# DNS in Application Architectures

Modern applications rely heavily on DNS.

Example:

```text
User
 |
 v
app.company.com
 |
 v
API
 |
 v
api.company.com
 |
 v

 |
 v

```

Each layer often uses DNS names instead of IP addresses.

This allows infrastructure teams to change IP addresses without changing application code.

# Common DNS Problems

## Record Does Not Exist

### Error

```text
Host not found
```

### Cause

Missing DNS record.

### Impact

Applications cannot locate services.

---

## Incorrect IP Address

### Error

```text
Application unreachable
```

### Cause

DNS points to the wrong server.

### Impact

Users may connect to an incorrect environment.

Example:

```text
Production hostname
     ->
Development server
```

---

## Expired Cache

### Error

```text
Users reach old server
```

### Cause

Cached entries have not expired.

### Impact

Users receive outdated DNS information.

---

## Slow DNS Server

### Error

```text
Application loads slowly
```

### Cause

Delayed DNS responses.

### Impact

Performance degradation.

---

## DNS Server Outage

### Error

```text
No applications accessible
```

### Cause

DNS infrastructure failure.

### Impact

Widespread service disruption.

# DNS Troubleshooting Process

When DNS issues are suspected:

### Step 1

Verify the hostname.

Example:

```text
orders.company.com
```

---

### Step 2

Perform a DNS lookup.

Example:

```bash
nslookup orders.company.com
```

---

### Step 3

Verify the returned IP address.

Example:

```text
Expected:
10.25.30.50

Actual:
10.25.30.99
```

---

### Step 4

Test connectivity to the returned address.

Example:

```bash
ping 10.25.30.50
```

---

### Step 5

Review DNS configuration and records.

---

# DNS Troubleshooting Tools

## nslookup

Queries DNS records.

Example:

```bash
nslookup orders.company.com
```

Example output:

```text
Name: orders.company.com
Address: 10.25.30.50
```

---

## dig

Provides detailed DNS information.

Example:

```bash
dig orders.company.com
```

Useful for:

- Record verification
- DNS troubleshooting
- TTL analysis

---

## ping

Verifies connectivity to resolved addresses.

Example:

```bash
ping orders.company.com
```

---

## ipconfig /flushdns

Clears DNS cache on Windows.

Example:

```cmd
ipconfig /flushdns
```

Useful after DNS updates.

# Production Support Case Study

## Incident

Users report that the Customer Portal is unavailable.

Application URL:

```text
portal.company.com
```

---

## Investigation

Application server:

```text
Healthy
```

Database:

```text
Healthy
```

Web server:

```text
Healthy
```

DNS query:

```text
portal.company.com
```

returns:

```text
10.20.5.100
```

Expected address:

```text
10.20.5.150
```

---

## Root Cause

Incorrect DNS record.

DNS was updated during deployment but pointed to the wrong server.

---

## Resolution

DNS record corrected.

Cache expired and users regained access.

---

## Lesson Learned

Applications rely on DNS before any communication can occur.

Even healthy applications appear offline when DNS is misconfigured.

# DNS and Production Support Best Practices

- Always verify DNS resolution during incident investigations.
- Use hostnames instead of hardcoded IP addresses when possible.
- Document DNS dependencies.
- Monitor DNS infrastructure.
- Validate DNS changes before deployments.
- Understand DNS cache behavior.
- Verify TTL settings before planned migrations.
