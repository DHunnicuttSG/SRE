# APIs and Network Traffic

## Learning Objectives

By the end of this lesson, students will be able to:

- Define an API and explain its purpose.
- Understand how APIs communicate across networks.
- Explain the relationship between APIs, HTTP, and HTTPS.
- Identify common API request methods.
- Interpret API responses and status codes.
- Understand common authentication mechanisms.
- Recognize common API-related production incidents.
- Use tools to test and troubleshoot APIs.
- Apply API concepts during Production Support investigations.

---

# Introduction

Modern applications rarely operate in isolation.

Most enterprise systems communicate with:

- Databases
- Third-party vendors
- Payment processors
- Authentication providers
- Cloud services
- Internal microservices

This communication typically occurs through APIs.

APIs have become the backbone of modern application integration and are critical to business operations.

Because of this, Production Support analysts frequently investigate incidents involving API failures, latency, authentication problems, and network communication issues.

Understanding APIs and network traffic is essential for effective troubleshooting.

---

# What Is an API?

API stands for:

```text
Application Programming Interface
```

An API is a set of rules that allows one application to communicate with another.

Think of an API as a waiter in a restaurant.

```text
Customer
    |
    v
Waiter
    |
    v
Kitchen
```

The customer submits a request.

The waiter delivers the request.

The kitchen processes it and returns a response.

An API performs the same function between applications.

---

# Why APIs Matter

Consider an online shopping application.

When a customer places an order:

```text
Website
   |
   +--> Payment Service
   |
   +--> Inventory Service
   |
   +--> Shipping Service
```

Each communication may occur through an API.

If any API fails:

```text
Order Processing Fails
```

Even when the application itself is healthy.

---

# API Communication Model

Most APIs use a request-response model.

```text
Client
   |
Request
   |
   v
API Server
   |
Response
   |
   v
Client
```

The client requests information.

The API processes the request.

The API returns a response.

# APIs and Network Traffic

Every API request generates network traffic.

Example:

```text
User
   |
Application
   |
API Request
   |
Customer Service API
```

Traffic travels across:

- Networks
- Routers
- Firewalls
- Load Balancers
- Application Servers

A failure anywhere in the path can affect API communication.

# API Rate Limiting

Rate limiting restricts the number of requests a client can make.

Example:

```text
100 Requests Per Minute
```

If exceeded:

```http
429 Too Many Requests
```

This protects backend systems from overload.

# Common API Production Incidents

## Authentication Failure

### Symptoms

```text
401 Unauthorized
```

### Root Cause

Expired token or invalid credentials.

---

## Backend Service Failure

### Symptoms

```text
500 Error
503 Error
```

### Root Cause

API dependency unreachable.

---

## DNS Failure

### Symptoms

```text
API Host Cannot Be Resolved
```

### Root Cause

Missing or incorrect DNS entry.

---

## Firewall Blocking Traffic

### Symptoms

```text
Connection Timeout
```

### Root Cause

Required traffic blocked by security rules.

---

## Rate Limiting

### Symptoms

```http
429 Too Many Requests
```

### Root Cause

Request threshold exceeded.

---

## SSL Certificate Failure

### Symptoms

```text
TLS Handshake Failed
```

### Root Cause

Expired or invalid certificate.

### 6. What does a 401 Unauthorized response indicate?

**Answer:**

The request could not be completed because authentication is missing, invalid, or expired.

Common causes include:

```text
Expired Token
Invalid Credentials
Missing Authentication Header
```

---

### 7. What does a 403 Forbidden response indicate?

**Answer:**

The user or application has authenticated successfully but does not have permission to access the requested resource.

---

### 8. What does a 503 Service Unavailable response indicate?

**Answer:**

The requested service is temporarily unavailable.

Possible causes:

```text
System Maintenance
Backend Service Failure
Load Balancer Issues
Capacity Problems
```

---

### 9. What is an API Gateway?

**Answer:**

An API Gateway is a service that sits between clients and APIs and provides capabilities such as:

```text
Authentication
Routing
Monitoring
Logging
Rate Limiting
```

---

### 10. What is rate limiting?

**Answer:**

Rate limiting restricts the number of requests a client can make within a defined period.

Example:

```text
100 Requests Per Minute
```

Rate limiting protects backend systems from excessive traffic.

---

### 11. What are the most common API data formats?

**Answer:**

The two most common formats are:

```text
JSON
XML
```

JSON is the most widely used format in modern APIs.

---

### 12. Why are APIs important in enterprise applications?

**Answer:**

APIs enable communication between applications, services, databases, and third-party systems.

# Hands-On Exercise

## Objective

Use common tools to investigate API communication and identify the root cause of API-related failures.

---

## Scenario

A customer-facing application retrieves data from an API.

Application URL:

```text
https://portal.company.com
```

API Endpoint:

```text
https://api.company.com/customers
```

Users report:

```text
Customer information cannot be displayed.
```

---

## Task 1: Verify DNS Resolution

Confirm that the API hostname resolves correctly.

### Windows

```cmd
nslookup api.company.com
```

### Linux

```bash
dig api.company.com
```

---

### Questions

1. Did the hostname resolve?
2. What IP address was returned?
3. What would happen if DNS resolution failed?

---

## Task 2: Verify Network Connectivity

Test connectivity to the API server.

### Windows

```powershell
Test-NetConnection api.company.com -Port 443
```

### Linux

```bash
telnet api.company.com 443
```

---

### Questions

1. Is Port 443 reachable?
2. What service typically uses Port 443?
3. What might prevent successful connectivity?

---

## Task 3: Send an API Request

Use curl to send a request.

```bash
curl https://api.company.com/customers
```

Example Response:

```json
{
  "customerId": 100,
  "name": "John Smith"
}
```

---

### Questions

1. Was a response received?
2. Did the response contain valid data?
3. Were any error messages returned?

---

## Task 4: Examine the Status Code

Request only the response headers.

```bash
curl -I https://api.company.com/customers
```

Possible Responses:

```http
200 OK
```

```http
401 Unauthorized
```

```http
500 Internal Server Error
```

```http
503 Service Unavailable
```

---

### Questions

1. What status code was returned?
2. What troubleshooting information does that code provide?
3. Is the issue likely network-related or application-related?

---

## Task 5: Investigate Authentication

Review authentication requirements.

Example:

```http
Authorization: Bearer eyJhbGciOi...
```

---

### Questions

1. Is authentication required?
2. Is the token valid?
3. Has the token expired?

---

## Task 6: Review API Dependencies

Document the communication path.

Example:

```text
User
  |
Portal Application
  |
API Gateway
  |
Customer API
  |
Database
```

---

### Questions

1. Which component appears most likely to be failing?
2. Could the issue originate from a dependency rather than the API itself?

# Summary

APIs have become the foundation of modern enterprise applications. Nearly every business application depends on APIs to communicate with databases, authentication systems, cloud services, and third-party providers. Because API communication crosses multiple layers of infrastructure, failures can originate from networking, authentication, certificates, firewalls, rate limits, backend services, or application logic.

Production Support professionals must understand how APIs communicate, how network traffic flows between systems, and how to interpret status codes, authentication failures, and connectivity issues. Mastering these concepts enables faster incident resolution, more effective troubleshooting, and improved application reliability.
