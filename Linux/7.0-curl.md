# Using the `curl` Command

## Learning Objectives

By the end of this lesson, students will be able to:

* Explain how `curl` transfers data from URLs.
* Download files and display response bodies.
* View response headers and HTTP status codes.
* Make GET and POST requests.
* Follow redirects and save downloads.
* Use `curl` to troubleshoot web requests.

---

## What Is `curl`?

`curl` is a command-line tool for transferring data to or from a server.
It supports protocols such as HTTP, HTTPS, FTP, and SFTP.

For web applications and APIs, `curl` is commonly used to:

* Test website availability.
* View HTTP response headers.
* Download files.
* Send GET and POST requests.
* Troubleshoot API responses.

Basic syntax:

```bash
curl [options] URL
```

---

## Display a Web Page

Use `curl` followed by a URL to display the response body:

```bash
curl https://example.com
```

This prints the website's HTML content in the terminal.

## Save a Response to a File

Use `-o` to choose the output file name:

```bash
curl -o example.html https://example.com
```

Use `-O` to save with the remote file name:

```bash
curl -O https://example.com/index.html
```

The download is silent unless `curl` encounters an error. Add `-sS` to hide
progress while still displaying errors:

```bash
curl -sS https://example.com
```

---

## Common Options

| Option | Description | Example |
| --- | --- | --- |
| `-i` | Include response headers in the output | `curl -i https://example.com` |
| `-I` | Request only response headers | `curl -I https://example.com` |
| `-L` | Follow redirects | `curl -L https://example.com` |
| `-o FILE` | Save output to a specific file | `curl -o page.html https://example.com` |
| `-O` | Save output using the remote file name | `curl -O https://example.com/file.zip` |
| `-s` | Hide the progress meter | `curl -s https://example.com` |
| `-S` | Show errors when silent mode is enabled | `curl -sS https://example.com` |
| `-v` | Show verbose connection details | `curl -v https://example.com` |
| `-X METHOD` | Specify an HTTP method | `curl -X POST https://example.com/api` |
| `-H` | Add or override an HTTP header | `curl -H "Accept: application/json" URL` |
| `-d` | Send data with a request | `curl -d "name=Alice" URL` |

## View Headers and Status Codes

Show response headers and the response body:

```bash
curl -i https://example.com
```

Request headers only:

```bash
curl -I https://example.com
```

Display only the HTTP status code:

```bash
curl -o /dev/null -s -w "%{http_code}\n" https://example.com
```

The status code tells you the result of the request. Common examples include:

| Code | Meaning |
| --- | --- |
| `200` | Request succeeded |
| `301` or `302` | Resource redirected |
| `400` | Invalid request |
| `401` | Authentication required |
| `403` | Request forbidden |
| `404` | Resource not found |
| `500` | Server error |

---

## Follow Redirects

Servers may redirect a request to a new URL. Use `-L` to follow redirects:

```bash
curl -L https://example.com
```

To download the final response after redirects:

```bash
curl -L -o result.html https://example.com
```

---

## Send GET Requests

GET is the default HTTP method used by `curl`:

```bash
curl https://api.example.com/users
```

Add a query parameter directly in the URL:

```bash
curl "https://api.example.com/users?active=true"
```

Quote URLs containing shell characters such as `&` and spaces.

---

## Send POST Requests

Send form data with `-d`:

```bash
curl -X POST \
  -d "name=Alice&role=student" \
  https://api.example.com/users
```

Send JSON data by setting the `Content-Type` header:

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -d '{"name":"Alice","role":"student"}' \
  https://api.example.com/users
```

By default, `-d` uses the `application/x-www-form-urlencoded` content type.

---

## Test a JSON API

`curl` works well with public test APIs. For example:

```bash
curl https://jsonplaceholder.typicode.com/posts/1
```

Request JSON explicitly and save it:

```bash
curl -H "Accept: application/json" \
  https://jsonplaceholder.typicode.com/posts/1 \
  -o post.json
```

If `jq` is installed, display the response in formatted JSON:

```bash
curl https://jsonplaceholder.typicode.com/posts/1 | jq
```

---

## Debug Requests

Use verbose mode to see request and connection details:

```bash
curl -v https://example.com
```

For more complete HTTPS troubleshooting:

```bash
curl -vk https://example.com
```

`-k` allows `curl` to continue with an invalid TLS certificate. It should
normally be used only for authorized testing because it bypasses certificate
verification.

## Practice Exercises

1. Display the HTML returned by `https://example.com`.

   ```bash
   curl https://example.com
   ```

2. Save the page as `example.html`.

   ```bash
   curl -o example.html https://example.com
   ```

3. Display only the response headers.

   ```bash
   curl -I https://example.com
   ```

4. Display the response headers and HTML body together.

   ```bash
   curl -i https://example.com
   ```

5. Print only the HTTP status code for `https://example.com`.

   ```bash
   curl -o /dev/null -s -w "%{http_code}\n" https://example.com
   ```

6. Retrieve one post from a JSON test API.

   ```bash
   curl https://jsonplaceholder.typicode.com/posts/1
   ```

7. Send a JSON POST request to a test API.

   ```bash
   curl -X POST \
     -H "Content-Type: application/json" \
     -d '{"title":"Linux lesson","body":"Testing curl","userId":1}' \
     https://jsonplaceholder.typicode.com/posts
   ```

8. Verbosely test the connection to `https://example.com`.

   ```bash
   curl -v https://example.com
   ```

---

## Key Takeaways

* `curl` transfers data to or from a URL.
* Use `-o` or `-O` to save a response.
* Use `-I` to request headers and `-i` to include headers with the body.
* Use `-L` to follow redirects.
* Use `-d` to send request data.
* Use `-H` to set HTTP headers.
* Use `-v` to troubleshoot request and connection problems.
