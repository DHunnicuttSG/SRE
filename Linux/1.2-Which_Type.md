# Finding Commands with `which` and `type`

## Learning Objectives

By the end of this lesson, students will be able to:

* Explain the difference between `which` and `type`.
* Locate executable files using `which`.
* Identify aliases, functions, shell built-ins, keywords, and executables
  using `type`.
* Troubleshoot unexpected command behavior.
* Find all executable matches in the shell's search path.

---

## Why Do These Commands Matter?

Linux may contain multiple versions of the same command. An alias or shell
function may also change what happens when you enter a command.

Use:

```bash
which command
type command
```

to determine which command the shell will execute.

---

## Using `which`

`which` searches the directories in the `PATH` environment variable for an
executable with the requested name.

```bash
which ls
```

Example result:

```text
/usr/bin/ls
```

This means the shell can find `ls` at `/usr/bin/ls`.

### Search for Multiple Commands

```bash
which ls cp tar
```

### Find All Matches in `PATH`

By default, `which` may display the first match. Use `-a` to show all matches
in the current `PATH`:

```bash
which -a python3
```

Example result:

```text
/usr/local/bin/python3
/usr/bin/python3
```

The shell normally runs the executable that appears first in `PATH`.

### Check the Current `PATH`

```bash
echo "$PATH"
```

Directories are separated by colons.

### Return Codes

* Exit status `0` means the command was found.
* A nonzero exit status means the command was not found.

For example:

```bash
which nonexistent_command
echo $?
```

The output from `echo $?` indicates whether the previous command succeeded.

### Limitations of `which`

`which` does not understand every type of shell command:

* Shell built-ins are not executable files.
* Aliases can redefine external commands.
* Functions do not always appear in the output from `which`.

Use `type` when diagnosing a command that may be a built-in, alias, keyword,
or function.

## Using `type`

`type` is a shell built-in in Bash and other common shells. It identifies how
the shell resolves a command name.

```bash
type ls
```

Example output:

```text
ls is /usr/bin/ls
```

The shell may resolve some names differently:

```bash
type cd
type printf
type for
```

Possible results include:

| Result | Meaning |
| --- | --- |
| `alias` | The name is an alias |
| `function` | The name is a shell function |
| `builtin` | The command is built into the shell |
| `keyword` | The name is reserved shell syntax |
| Path | The shell found an executable file |

### Display All Results

Use `-a` to display all matching executables and other command definitions:

```bash
type -a ls
```

Example:

```text
ls is aliased to 'ls --color=auto'
ls is /usr/bin/ls
```

This output can reveal an alias that overrides an executable.

### Display Only the Executable Path

Use `-p` to display the executable path without reporting aliases, functions,
or built-ins:

```bash
type -p python3
```

### Check Whether a Command Exists

Use `-t` to return a short command type:

```bash
type -t cd
type -t ls
type -t nonexistent_command
```

Possible output includes:

```text
builtin
file
alias
function
keyword
```

`type -t` prints nothing if the command does not exist.

## Aliases and Functions

If a command has unexpected output, check whether it is aliased:

```bash
type ls
alias ls
```

Example alias:

```bash
alias ll='ls -alF'
type ll
```

Example output:

```text
ll is aliased to 'ls -alF'
```

Check a shell function:

```bash
function greeting() {
    echo "Hello"
}

type greeting
```

---

## `which` Compared with `type`

| Task | Recommended command | Example |
| --- | --- | --- |
| Locate an executable in `PATH` | `which` | `which python3` |
| Show all executable matches | `which -a` | `which -a python3` |
| Identify an alias, function, or built-in | `type` | `type cd` |
| Display all ways a name can resolve | `type -a` | `type -a ls` |
| Display only an executable path | `type -p` | `type -p python3` |

Use `type` for general shell troubleshooting. Use `which` when you specifically
need to locate an executable in `PATH`.

---

## Troubleshooting a Command

Suppose a command named `python` behaves differently than expected:

```bash
type -a python
which -a python
python --version
```

The `type` and `which` results show each executable and whether a shell alias
changes the name. The final command confirms the selected Python version.

For shell built-ins, use `type` instead of expecting an executable path:

```bash
type cd
type echo
```

Both commands may execute shell-provided functionality rather than a file in
`PATH`.

## Practice Exercises

1. Find the executable used for `ls`.

   ```bash
   which ls
   ```

2. Find every `python3` executable in `PATH`.

   ```bash
   which -a python3
   ```

3. Identify how Bash resolves `cd`.

   ```bash
   type cd
   ```

4. Identify how Bash resolves `ls`.

   ```bash
   type ls
   ```

5. Display all matches for `ls`.

   ```bash
   type -a ls
   ```

6. Locate the executable path for `python3`.

   ```bash
   type -p python3
   ```

7. Check the type of the `echo` command.

   ```bash
   type -t echo
   ```

8. Create an alias and check how the shell resolves it.

   ```bash
   alias l='ls -alh'
   type l
   ```

9. Create a shell function and identify it with `type`.

   ```bash
   function greeting() {
       echo "Hello"
   }

   type greeting
   ```

10. View the current executable search path.

    ```bash
    echo "$PATH"
    ```

---

## Key Takeaways

* `which` finds executable files in `PATH`.
* `which -a` displays all matching executable files.
* `type` identifies aliases, functions, built-ins, keywords, and executable
  files.
* Use `type -a` to inspect multiple definitions and executable matches.
* Use `type -p` to locate an executable path.
* Use `type` first when troubleshooting unexpected shell command behavior.
