# Introduction

Many modern applications no longer run entirely within traditional on-premises data centers.

Instead, organizations host applications in cloud environments such as:

```text
Microsoft Azure
Amazon Web Services (AWS)
Google Cloud Platform (GCP)
```

Although the servers may be virtual, networking fundamentals remain critical.

Cloud applications still require:

- IP addresses
- DNS
- Routing
- Firewalls
- Load balancing
- Secure communications

Production Support professionals frequently troubleshoot cloud-hosted applications and must understand how cloud networking works.

---

# What Is Cloud Networking?

Cloud networking refers to the virtual networking infrastructure that connects cloud resources.

Just like traditional networking, cloud networking enables communication between:

```text
Users
Applications
Databases
APIs
Storage Services
```

The difference is that networking components are software-defined and managed through cloud platforms rather than physical hardware.

---

# Traditional vs Cloud Networking

## Traditional Networking

Uses physical hardware.

Examples:

```text
Routers
Switches
Firewalls
Cables
Data Centers
```

---

## Cloud Networking

Uses software-defined components.

Examples:

```text
Virtual Networks
Virtual Routers
Security Groups
Cloud Load Balancers
Virtual Firewalls
```

The underlying concepts remain the same.

---

# Cloud Networking Architecture

Example:

```text
Users
   |
Internet
   |
Cloud Load Balancer
   |
Web Servers
   |
Application Servers
   |
Database Servers
```

Although the infrastructure is virtual, networking still controls communication between components.

---

# Virtual Networks

A Virtual Network is a logically isolated network within a cloud environment.

Examples:

```text
Azure Virtual Network (VNet)

AWS Virtual Private Cloud (VPC)

Google VPC
```

Think of a virtual network as your private section of the cloud.

---

## Example VNet

```text
Production VNet

10.10.0.0/16
```

Contains:

```text
Web Servers
Application Servers
Database Servers
```

Only authorized communication is allowed.

---

# Why Virtual Networks Matter

Virtual networks provide:

- Isolation
- Security
- Network segmentation
- Controlled communication

Without network isolation:

```text
All cloud customers could potentially interact.
```

Virtual networks prevent this.

---

# Subnets

A subnet divides a larger network into smaller segments.

Example:

```text
Virtual Network

10.10.0.0/16
```

Subnets:

```text
Web Tier      10.10.1.0/24

App Tier      10.10.2.0/24

DB Tier       10.10.3.0/24
```

---

# Benefits of Subnets

Subnets provide:

- Better security
- Easier management
- Network segmentation
- Improved traffic control

---

# Example Three-Tier Architecture

```text
Users
   |
Web Subnet
   |
Application Subnet
   |
Database Subnet
```

Each subnet can have unique security controls.

---

# Public vs Private Subnets

## Public Subnet

Can communicate directly with the Internet.

Examples:

```text
Web Servers
Load Balancers
API Gateways
```

---

## Private Subnet

Cannot communicate directly with the Internet.

Examples:

```text
Databases
Backend Services
Internal APIs
```

Private subnets improve security by limiting exposure.

---

# IP Addressing in the Cloud

Cloud resources require IP addresses just like traditional servers.

Resources may have:

```text
Private IP Address
```

and optionally:

```text
Public IP Address
```

---

## Example

Private Address:

```text
10.10.2.15
```

Public Address:

```text
52.165.120.10
```

External users communicate with public addresses.

Internal systems often communicate using private addresses.

---

# Routing in Cloud Networks

Routing determines where traffic travels.

Cloud platforms maintain routing tables that control network paths.

Example:

```text
Web Tier
   |
App Tier
   |
Database Tier
```

Traffic follows routes defined by the cloud environment.

---

# Route Tables

Route tables contain rules that direct traffic.

Example:

```text
Destination: 0.0.0.0/0

Next Hop: Internet Gateway
```

Meaning:

```text
All unknown traffic goes to the Internet.
```

---

# Security Groups

Security Groups act as virtual firewalls.

Cloud providers use different names:

```text
AWS Security Groups

Azure Network Security Groups (NSGs)

Google Firewall Rules
```

---

## Example Security Group

Allow:

```text
TCP 443
```

Allow:

```text
TCP 1433
```

Deny:

```text
Everything Else
```

---

# Network Security Groups (Azure)

Azure uses Network Security Groups (NSGs).

An NSG controls:

- Source
- Destination
- Protocol
- Port
- Action

Example:

```text
Allow HTTPS 443

Allow SQL 1433

Deny All Others
```

---

# Internet Gateways

Cloud environments use Internet Gateways to provide Internet access.

Example:

```text
Users
  |
Internet
  |
Internet Gateway
  |
Cloud Resources
```

Without an Internet Gateway:

```text
No Internet Connectivity
```

---

# NAT Gateway

NAT stands for:

```text
Network Address Translation
```

NAT Gateways allow private resources to access the Internet without being directly exposed.

Example:

```text
Private Server
      |
NAT Gateway
      |
Internet
```

The server can initiate outbound traffic but cannot be reached directly from the Internet.

---

# Load Balancers in the Cloud

Cloud load balancers distribute traffic across multiple resources.

Examples:

```text
Azure Load Balancer

Azure Application Gateway

AWS Elastic Load Balancer

Google Cloud Load Balancer
```

Benefits:

- High Availability
- Scalability
- Fault Tolerance

---

# DNS in Cloud Environments

Cloud applications rely heavily on DNS.

Examples:

```text
api.company.com

portal.company.com
```

DNS resolves hostnames to cloud-hosted services.

Cloud environments often provide:

```text
Private DNS

Public DNS
```

---

# Hybrid Networking

Many organizations operate in hybrid environments.

Example:

```text
On-Premises Data Center
          |
          |
VPN / ExpressRoute
          |
          |
Cloud Network
```

Applications may communicate across both environments.

---

# VPN Connectivity

VPN stands for:

```text
Virtual Private Network
```

VPNs create encrypted communication between:

```text
On-Premises Network
```

and

```text
Cloud Environment
```

---

# ExpressRoute and Direct Connect

Organizations often use dedicated connections.

Examples:

```text
Azure ExpressRoute

AWS Direct Connect
```

Benefits:

- Lower latency
- Improved reliability
- Better security

---

# Common Cloud Networking Problems

## Security Group Blocking Traffic

### Symptoms

```text
Connection Timeout
```

### Cause

Required port not allowed.

---

## Routing Misconfiguration

### Symptoms

```text
Server Unreachable
```

### Cause

Invalid route table.

---

## DNS Failure

### Symptoms

```text
Host Not Found
```

### Cause

Missing DNS entry.

---

## Load Balancer Health Check Failure

### Symptoms

```text
Application Unavailable
```

### Cause

Healthy servers marked unavailable.

---

## VPN Failure

### Symptoms

```text
Cloud Resources Cannot Reach On-Prem Systems
```

### Cause

VPN outage or configuration issue.

---

# Cloud Networking Troubleshooting Process

## Step 1

Verify DNS.

```bash
nslookup app.company.com
```

---

## Step 2

Verify connectivity.

```powershell
Test-NetConnection app.company.com -Port 443
```

---

## Step 3

Review Security Groups.

Confirm required ports are allowed.

---

## Step 4

Review Route Tables.

Verify traffic paths.

---

## Step 5

Review Load Balancer Health Checks.

---

## Step 6

Review Application and Cloud Logs.

# Production Support Case Study

## Incident

Users cannot access a cloud-hosted portal.

---

## Investigation

DNS:

```text
Successful
```

Load Balancer:

```text
Healthy
```

Application Servers:

```text
Running
```

Connectivity Test:

```text
Failed
```

---

## Findings

A Network Security Group was updated.

New configuration:

```text
HTTPS 443 Blocked
```

---

## Root Cause

Security Group configuration blocked application traffic.

---

## Resolution

Restore HTTPS access.

Validate application functionality.

---

## Lesson Learned

Cloud networking issues often resemble application failures.

Network and security configurations should always be reviewed during investigations.

# Key Takeaways

- Cloud networking uses software-defined networking components.
- VNets and VPCs provide isolated cloud networks.
- Subnets divide networks into manageable segments.
- Security Groups and NSGs function as cloud firewalls.
- Route Tables control traffic flow.
- Load Balancers improve scalability and availability.
- VPNs and dedicated connections enable hybrid networking.
- Understanding cloud networking is essential for supporting modern applications.

# Summary

Cloud networking provides the foundation for communication between cloud-hosted resources, users, and external systems. Although implemented through software-defined infrastructure, the same networking principles apply: IP addressing, routing, security, DNS, and load balancing.

Production Support professionals increasingly support applications hosted in Azure, AWS, and other cloud platforms. Understanding virtual networks, subnets, security groups, routing, hybrid connectivity, and cloud load balancing allows support teams to troubleshoot issues more effectively and maintain reliable, secure application environments.
