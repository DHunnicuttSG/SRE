# SQL Window Functions

## What Is a Window Function?

A **window function** calculates a value across a set of related rows while keeping the individual rows in the result.

For example, `GROUP BY` can return one row per Level with its maximum Workout duration. A window function can show every Workout and also show the maximum duration for that Workout's Level.

Window functions are useful for:

- Numbering or ranking rows within groups
- Calculating running totals and counts
- Comparing a row with other rows in its group
- Reading a previous or next row
- Adding group-level statistics without collapsing detail rows

The examples in this guide use MySQL 8.0 and the `PersonalTrainer` database. MySQL 8.0 is required for window-function support.

---

## Window Function Syntax

A window function uses an `OVER` clause:

```sql
function_name(expression) OVER (
    PARTITION BY group_column
    ORDER BY sort_column
    frame_clause
)
```

The parts are optional depending on the function and task:

- **Function:** For example, `ROW_NUMBER()`, `SUM()`, `LAG()`, or `AVG()`.
- **`PARTITION BY`:** Divides rows into independent groups. Similar to grouping, but it does not combine the rows.
- **`ORDER BY`:** Defines the order in which a ranking or ordered calculation is applied.
- **Frame clause:** Defines which rows in the ordered partition are included in a frame-based calculation.

The `OVER` clause is what makes the function a window function.

## Window Functions Versus `GROUP BY`

An aggregate query groups rows into fewer result rows:

```sql
SELECT
    LevelId,
    MAX(MaxMinutes) LevelMaxMinutes
FROM Workout
GROUP BY LevelId;
```

This returns one row per Level.

A window aggregate retains each Workout:

```sql
SELECT
    w.`Name` WorkoutName,
    w.LevelId,
    w.MaxMinutes,
    MAX(w.MaxMinutes) OVER (
        PARTITION BY w.LevelId
    ) LevelMaxMinutes
FROM Workout w
ORDER BY w.LevelId, w.MaxMinutes DESC;
```

This returns one row per Workout, with the maximum duration for its Level repeated on each row.

## Ranking Functions

MySQL provides three commonly used ranking functions:

| Function | What It Does | How Ties Are Numbered |
| -------- | ------------ | --------------------- |
| `ROW_NUMBER()` | Assigns a unique sequential number | Tied rows still get different numbers |
| `RANK()` | Assigns a rank and leaves gaps after ties | A tie at rank 1 is followed by rank 3 |
| `DENSE_RANK()` | Assigns a rank without gaps | A tie at rank 1 is followed by rank 2 |

### Number Workouts Within Each Level

```sql
SELECT
    w.`Name` WorkoutName,
    w.LevelId,
    w.MaxMinutes,
    ROW_NUMBER() OVER (
        PARTITION BY w.LevelId
        ORDER BY w.MaxMinutes DESC, w.`Name`
    ) LevelRowNumber
FROM Workout w
ORDER BY w.LevelId, LevelRowNumber;
```

The `PARTITION BY` restarts numbering for each Level. The second sort key makes the ordering predictable when two Workouts have the same `MaxMinutes`.

### Rank Workouts, Preserving Ties

```sql
SELECT
    w.`Name` WorkoutName,
    w.LevelId,
    w.MaxMinutes,
    RANK() OVER (
        PARTITION BY w.LevelId
        ORDER BY w.MaxMinutes DESC
    ) LevelRank
FROM Workout w
ORDER BY w.LevelId, LevelRank, w.`Name`;
```

Do not add a unique tie-breaker to the `RANK()` window's `ORDER BY` if tied `MaxMinutes` values are supposed to share the same rank. A tie-breaker belongs in the final query ordering if a stable display order is needed.

## Filtering to the Top Rows

Window functions are calculated after `WHERE` filtering in a query block. Therefore, a window-function result cannot normally be filtered in that same query block's `WHERE` clause.

Use a derived table or a CTE to calculate the row number first, then filter it outside:

```sql
SELECT
    ranked.City,
    ranked.FirstName,
    ranked.LastName,
    ranked.CityPosition
FROM (
    SELECT
        c.City,
        c.FirstName,
        c.LastName,
        ROW_NUMBER() OVER (
            PARTITION BY c.City
            ORDER BY c.LastName, c.FirstName, c.ClientId
        ) CityPosition
    FROM Client c
) ranked
WHERE ranked.CityPosition <= 3
ORDER BY ranked.City, ranked.CityPosition;
```

The inner query numbers Clients independently within each City. The outer query keeps only the first three in each City.

## Aggregate Window Functions

Aggregate functions such as `SUM()`, `COUNT()`, `AVG()`, `MIN()`, and `MAX()` can be used as window functions.

### Cumulative Count

```sql
SELECT
    i.ClientId,
    i.InvoiceId,
    i.InvoiceDate,
    COUNT(*) OVER (
        PARTITION BY i.ClientId
        ORDER BY i.InvoiceDate, i.InvoiceId
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) RunningInvoiceCount
FROM Invoice i
ORDER BY i.ClientId, i.InvoiceDate, i.InvoiceId;
```

The explicit frame includes every row from the start of the Client's ordered partition through the current Invoice.

### Running Totals After Aggregation

An Invoice has one or more line items. First calculate one total per Invoice; then apply the window sum to those invoice rows:

```sql
SELECT
    paid.ClientId,
    paid.InvoiceId,
    paid.InvoiceDate,
    paid.InvoiceTotal,
    SUM(paid.InvoiceTotal) OVER (
        PARTITION BY paid.ClientId
        ORDER BY paid.InvoiceDate, paid.InvoiceId
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) RunningPaidTotal
FROM (
    SELECT
        i.ClientId,
        i.InvoiceId,
        i.InvoiceDate,
        SUM(li.Price * li.Quantity) InvoiceTotal
    FROM Invoice i
    INNER JOIN InvoiceLineItem li ON i.InvoiceId = li.InvoiceId
    WHERE i.InvoiceStatus = 2
    GROUP BY i.ClientId, i.InvoiceId, i.InvoiceDate
) paid
ORDER BY paid.ClientId, paid.InvoiceDate, paid.InvoiceId;
```

The subquery ensures that the window operates on one row per paid Invoice, not one row per line item. A CTE can make this multi-step query easier to read; see [Common Table Expressions](./2.2_Common_Table_Expressions.md).

## Window Frames

A **window frame** specifies which rows around the current row contribute to an aggregate window calculation.

This frame describes a running calculation:

```sql
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

It includes rows from the beginning of the partition through the current row.

Frames matter most for ordered aggregate windows. When an `ORDER BY` is present and the frame is omitted, the database's default frame can include peer rows with the same ordering value. This may produce surprising running totals when values tie. Use an explicit frame when you mean a row-by-row running calculation.

For deterministic results, give the window an ordering that uniquely orders rows when the calculation depends on row sequence. An invoice date alone may not be unique, so examples use both `InvoiceDate` and `InvoiceId`.

## Looking at Neighboring Rows

`LAG()` reads a value from a preceding row in the partition. `LEAD()` reads from a following row.

This query finds the previous InvoiceDate for each Client:

```sql
SELECT
    i.ClientId,
    i.InvoiceId,
    i.InvoiceDate,
    LAG(i.InvoiceDate) OVER (
        PARTITION BY i.ClientId
        ORDER BY i.InvoiceDate, i.InvoiceId
    ) PreviousInvoiceDate,
    DATEDIFF(
        i.InvoiceDate,
        LAG(i.InvoiceDate) OVER (
            PARTITION BY i.ClientId
            ORDER BY i.InvoiceDate, i.InvoiceId
        )
    ) DaysSincePreviousInvoice
FROM Invoice i
ORDER BY i.ClientId, i.InvoiceDate, i.InvoiceId;
```

The first Invoice for each Client has no previous Invoice, so `LAG()` returns `NULL` for that row. `DATEDIFF()` also returns `NULL` when either date is `NULL`.

## Grouping Before Ranking

Window functions operate on the rows produced by the query block. To rank aggregated results, first group the rows and then apply the window function to those grouped rows. A derived table or CTE makes that order explicit.

```sql
SELECT
    goal_counts.GoalId,
    goal_counts.GoalName,
    goal_counts.ClientCount,
    DENSE_RANK() OVER (
        ORDER BY goal_counts.ClientCount DESC
    ) PopularityRank
FROM (
    SELECT
        g.GoalId,
        g.`Name` GoalName,
        COUNT(cg.ClientId) ClientCount
    FROM Goal g
    LEFT JOIN ClientGoal cg ON g.GoalId = cg.GoalId
    GROUP BY g.GoalId, g.`Name`
) goal_counts
ORDER BY PopularityRank, goal_counts.GoalName;
```

The inner query produces one row per Goal. The outer query ranks those rows by how many Clients selected each Goal.

## Common Mistakes

### Filtering a Window Result Too Early

This is not valid in MySQL because the window result is not available in the `WHERE` clause of the same query block:

```sql
SELECT
    c.City,
    ROW_NUMBER() OVER (PARTITION BY c.City ORDER BY c.LastName) CityPosition
FROM Client c
WHERE CityPosition <= 3;
```

Calculate the window result in a derived table or CTE, then filter in the outer query.

### Confusing `PARTITION BY` with `GROUP BY`

`PARTITION BY` defines the rows a window calculation can see, but it preserves those rows. `GROUP BY` combines rows into groups.

### Forgetting Ties

`ROW_NUMBER()` always assigns different numbers. Use `RANK()` or `DENSE_RANK()` when equal values should share a rank.

### Using the Wrong Calculation Grain

If a window should calculate running invoice totals, first reduce line items to one row per Invoice. Otherwise, each line item becomes a separate step in the running sum.

### Relying on Accidental Ordering

Row order is not guaranteed unless the final query includes an `ORDER BY`. A window's `ORDER BY` controls the calculation but does not guarantee the presentation order of the final result.

## Summary

| Feature | Use |
| ------- | --- |
| `PARTITION BY` | Divide rows into independent calculation groups |
| `ROW_NUMBER()` | Assign unique sequential positions |
| `RANK()` | Rank rows while leaving gaps after ties |
| `DENSE_RANK()` | Rank rows without gaps after ties |
| Aggregate `OVER()` | Calculate group or running statistics without collapsing detail rows |
| Window frame | Define the rows used by an ordered aggregate |
| `LAG()` / `LEAD()` | Read a value from a previous or following row |
| Derived table or CTE | Filter or reuse a calculated window result |

Use window functions when each detail row should remain visible alongside a rank, comparison, or aggregate. Define partitions and ordering carefully, and use an explicit frame for running aggregates.
