## Learning Objectives

- Identify common TCP and UDP ports.
- Understand the relationship between IP addresses, ports, and protocols.

- Use basic networking tools to test connectivity.
- Troubleshoot connectivity issues involving ports and protocols.

---

# Introduction

Applications communicate over networks using a combination of:

- IP Addresses
- Ports
- Protocols

Think of these three components as addressing information for network communication.

```text
IP Address = Building Address
Port = Department or Office Number
Protocol = Language Used for Communication
```

For two systems to communicate successfully:

1. The destination device must be reachable.
2. The correct port must be available.
3. Both systems must understand the same protocol.

Many Production Support incidents occur because one of these components is misconfigured or unavailable.

---

# What Is a Protocol?

A protocol is a set of rules that defines how devices communicate across a network.

Protocols determine:

- How connections are established
- How data is transmitted
- How errors are handled
- How communication is terminated

Without protocols, devices would not know how to exchange information.

---

Some of the most commonly used protocols include:

| Protocol | Purpose |

Production Support analysts encounter many of these protocols daily when reviewing logs and troubleshooting applications.

# What Is a Port?

A port is a logical communication endpoint on a device.

While an IP address identifies a device, a port identifies a specific service running on that device.

Example:

```text
Server IP:
10.10.20.50

Available Services:

Port 80    -> HTTP
Port 443   -> HTTPS
Port 1433  -> SQL Server
```

A server can host multiple services simultaneously because each service listens on a different port.

---

# Why Ports Matter

Consider a server with the following services:

```text
10.10.20.50
```

Running:

```text
Web Application
Database
API Service
```

How does traffic know which service to access?

Using ports:

```text
10.10.20.50:443
```

Connects to:

```text
HTTPS Web Service
```

While:

```text
10.10.20.50:1433
```

Connects to:

```text
SQL Server
```

The same IP address can support many services because each service uses a unique port.

# Port Number Ranges

Port numbers range from:

```text
0 - 65535
```

They are divided into three categories.

---

## Well-Known Ports

Range:

```text
0 - 1023
```

Reserved for common services.

Examples:

```text
80   HTTP
443  HTTPS
22   SSH
21   FTP
53   DNS
25   SMTP
```

---

## Registered Ports

Range:

```text
1024 - 49151
```

Typically assigned to specific applications.

Examples:

```text
1433 SQL Server
1521 Oracle
3306 MySQL
5432 PostgreSQL
```

---

## Dynamic (Ephemeral) Ports

Range:

```text
49152 - 65535
```

Used temporarily by client applications.

Example:

```text
Browser
   |
   v
Uses random temporary port
```

when connecting to:

```text
HTTPS Port 443
```

# Understanding Client and Server Communication

When a user accesses a website:

```text
https://orders.company.com
```

Communication might look like:

```text
Client:
192.168.1.50:52341

Server:
10.20.30.40:443
```

Explanation:

```text
52341 = Temporary client port
443   = HTTPS service port
```

The client initiates communication using a temporary port.

The server listens on a well-known port.

# TCP and UDP

Most protocols operate over either TCP or UDP.

These are known as transport-layer protocols.

---

# TCP (Transmission Control Protocol)

TCP is a reliable, connection-oriented protocol.

Characteristics:

- Reliable delivery
- Error checking
- Packet sequencing
- Acknowledgments
- Guaranteed transmission

Example uses:

- Web applications
- APIs
- Database communication
- Email systems

---

## TCP Connection Process

TCP establishes communication using a process called the Three-Way Handshake.

```text
Client -> SYN
Server -> SYN-ACK
Client -> ACK
```

After the handshake completes:

```text
Connection Established
```

This ensures both devices are ready to communicate.

---

## Common TCP Protocols

| Protocol | Port |
|-----------|-----------|
| HTTP | 80 |
| HTTPS | 443 |
| SSH | 22 |
| FTP | 21 |
| SMTP | 25 |
| SQL Server | 1433 |
| Oracle | 1521 |
| MySQL | 3306 |
| PostgreSQL | 5432 |

---

# UDP (User Datagram Protocol)

UDP is a connectionless protocol.

Characteristics:

- Fast
- Lightweight
- Minimal overhead
- No delivery guarantees

UDP prioritizes speed over reliability.

---

## Common UDP Protocols

| Protocol | Port |
|-----------|-----------|
| DNS | 53 |
| DHCP | 67/68 |
| NTP | 123 |
| SNMP | 161 |
| VoIP Services | Various |

---

# TCP vs UDP Comparison

| Feature | TCP | UDP |
|----------|----------|----------|
| Reliable Delivery | Yes | No |
| Connection Required | Yes | No |
| Error Checking | Yes | Limited |
| Speed | Slower | Faster |
| Common Uses | Web, APIs, Databases | DNS, Streaming, VoIP |

# Ports and Firewalls

Firewalls determine which ports can accept communication.

Example:

```text
Application Server
        |
        | Port 1433
        |
Database Server
```

If the firewall blocks port 1433:

```text
Connection Fails
```

The application may appear broken even though all services are running correctly.

---

# Open vs Closed Ports

## Open Port

Service is listening and accepting connections.

Example:

```text
HTTPS Port 443
```

Status:

```text
OPEN
```

Connections succeed.

---

## Closed Port

No service is listening.

Example:

```text
443
```

Status:

```text
CLOSED
```

Connections fail immediately.

---

## Filtered Port

Traffic is blocked by a firewall.

Status:

```text
FILTERED
```

Result:

```text
Connection Timeout
```

---

# Common Port-Related Errors

## Connection Refused

Meaning:

```text
Target reached
But service not listening
```

Possible causes:

- Service stopped
- Wrong port
- Configuration issue

---

## Connection Timed Out

Meaning:

```text
No response received
```

Possible causes:

- Firewall block
- Routing issue
- Network outage

---

## Host Unreachable

Meaning:

```text
Unable to reach destination system
```

Possible causes:

- DNS issue
- Incorrect IP address
- Network failure

# Connectivity Testing Tools

## Telnet

Tests whether a port is reachable.

Example:

```bash
telnet server01 443
```

Success indicates the port is open and reachable.

---

## PowerShell Test-NetConnection

Windows method for port testing.

Example:

```powershell
Test-NetConnection server01 -Port 443
```

Useful in enterprise environments.

---

## Netstat

Displays active connections and listening ports.

Example:

```bash
netstat -an
```

Can help identify whether a service is listening on the expected port.

---

## ss

Modern Linux utility for socket information.

Example:

```bash
ss -tuln
```

Displays listening TCP and UDP services.

---

## curl

Tests web service connectivity.

Example:

```bash
curl https://orders.company.com
```

Useful for API and web application troubleshooting.

# Production Support Scenario

## Incident

Users cannot submit orders through a web application.

Application logs display:

```text
Database Connection Timeout
```

---

## Investigation

Application Server:

```text
Healthy
```

Database Server:

```text
Healthy
```

Ping Test:

```text
Successful
```

Port Test:

```text
1433 Unreachable
```

Firewall Review:

```text
Port 1433 blocked
```

---

## Root Cause

Database traffic blocked by a firewall rule.

---

## Resolution

Firewall rule updated.

Port opened.

Application connectivity restored.

---

## Lesson Learned

Systems can be operational while communication remains impossible due to blocked ports.

Always verify port accessibility during troubleshooting.

# Best Practices for Production Support

- Know the common ports used by supported applications.
- Verify connectivity before escalating incidents.
- Document application dependencies and required ports.
- Work closely with networking and security teams.
- Include port validation in deployment testing.
- Monitor critical service ports.
- Understand firewall rules affecting application traffic.

- Understanding ports and protocols is essential for Production Support troubleshooting.
