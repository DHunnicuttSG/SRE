# Introduction

Most modern applications communicate using HTTP or HTTPS.

Whenever a user:

- Opens a website
- Uses a web application
- Calls an API
- Logs into a portal
- Submits an online form

HTTP or HTTPS is typically involved.

Because so many business applications rely on web technologies, understanding HTTP and HTTPS is one of the most important skills for Production Support professionals.

Many incidents involve:

- Website failures
- API errors
- Authentication problems
- SSL certificate issues
- Performance bottlenecks

A working knowledge of HTTP and HTTPS allows support analysts to identify and resolve these issues more quickly.

---

# What Is HTTP?

HTTP stands for:

```text
HyperText Transfer Protocol
```

HTTP is the protocol used to transfer information between:

- Web browsers
- Web servers
- APIs
- Cloud applications

HTTP defines how clients and servers communicate.

Example:

```text
Browser -> Request

Server -> Response
```

---

# What Is HTTPS?

HTTPS stands for:

```text
HyperText Transfer Protocol Secure
```

HTTPS is HTTP with encryption provided by SSL/TLS.

HTTPS provides:

- Encryption
- Data integrity
- Authentication

HTTPS ensures that information cannot easily be read or modified while traveling across a network.

---

# HTTP vs HTTPS

## HTTP

Characteristics:

- Data transferred in plain text
- No encryption
- Less secure

Example:

```text
http://company.com
```

Default Port:

```text
80
```

---

## HTTPS

Characteristics:

- Data encrypted
- More secure
- Protects sensitive information

Example:

```text
https://company.com
```

Default Port:

```text
443
```

---

# Why HTTPS Matters

Imagine a user entering:

```text
Username
Password
Credit Card Information
```

Without encryption:

```text
Data could potentially be intercepted.
```

With HTTPS:

```text
Data is encrypted before transmission.
```

This is why nearly all modern applications require HTTPS.

# Client-Server Communication

HTTP follows a client-server model.

### Client

The system making the request.

Examples:

- Browser
- Mobile App
- API Consumer

---

### Server

The system responding to requests.

Examples:

- Web Server
- Application Server
- API Endpoint

---

# HTTP Request-Response Model

Communication occurs through requests and responses.

```text
Client
   |
   | HTTP Request
   v
Server
   |
   | HTTP Response
   v
Client
```

The client asks for information.

The server returns a response.

---

# Example HTTP Request

A browser requests a webpage.

```http
GET /products HTTP/1.1
Host: company.com
```

Meaning:

```text
Request the products page.
```

---

# Example HTTP Response

```http
HTTP/1.1 200 OK
```

Meaning:

```text
Request processed successfully.
```

The server then returns data to the client.

# Anatomy of a URL

Example:

```text

```

Components:

```text
https://       Protocol
orders         Hostname
company.com    Domain
/products      Resource Path

```

Understanding URLs helps analysts troubleshoot routing and application issues.

# HTTP Methods

HTTP methods define the action being requested.

---

# GET

Retrieves information.

Example:

```http
GET /products
```

Use Cases:

- View products
- Retrieve customer information
- Display reports

GET does not modify data.

---

# POST

Creates new information.

Example:

```http
POST /orders
```

Use Cases:

- Create orders
- Submit forms
- Add new records

POST typically changes data.

---

# PUT

Updates existing information.

Example:

```http
PUT /customers/100
```

Use Cases:

- Update customer profile
- Modify records

---

# DELETE

Removes information.

Example:

```http
DELETE /orders/100
```

Use Cases:

- Delete records
- Remove resources

---

# PATCH

Partially updates existing data.

Example:

```http
PATCH /customers/100
```

Use Cases:

- Update a specific field
- Modify portions of a record

---

# Common HTTP Methods Summary

| Method | Purpose |
|----------|----------|
| GET | Retrieve data |
| POST | Create data |
| PUT | Update existing data |
| PATCH | Partially update data |
| DELETE | Remove data |

# SSL and TLS

SSL (Secure Sockets Layer) and TLS (Transport Layer Security) provide encryption for HTTPS communication.

Their responsibilities include:

- Encrypting data
- Preventing eavesdropping
- Verifying server identity
- Protecting sensitive information

Modern applications primarily use TLS, although SSL is still commonly referenced.

---

# HTTPS Connection Process

When a user visits:

```text
https://orders.company.com
```

The process is:

```text
1. DNS Resolution
2. TCP Connection
3. TLS Handshake
4. Certificate Validation
5. Secure Communication Begins
```

Only after successful TLS validation can encrypted communication occur.

---

# Common HTTPS Problems

## Expired Certificate

Symptoms:

```text
Certificate Warning
Secure Connection Failed
```

Impact:

```text
Users may be unable to access the application.
```

---

## Invalid Certificate

Symptoms:

```text
Browser Security Warning
```

Impact:

```text
Users lose trust in the application.
```

---

## Certificate Mismatch

Symptoms:

```text
Hostname Does Not Match Certificate
```

Impact:

```text
TLS Handshake Failure
```

---

## TLS Version Mismatch

Symptoms:

```text
Unable To Establish Secure Connection
```

Impact:

```text
Modern clients reject older protocols.
```

# Useful HTTP Troubleshooting Tools

Production Support professionals frequently use a variety of tools to investigate web applications, APIs, and connectivity issues. Understanding these tools can significantly reduce troubleshooting time and improve incident resolution.

---

## Browser Developer Tools

Modern web browsers include built-in developer tools that allow analysts to inspect HTTP and HTTPS traffic.

Capabilities include:

- Viewing requests and responses
- Examining HTTP headers
- Identifying HTTP status codes
- Measuring page load times
- Troubleshooting JavaScript errors
- Inspecting cookies and session information

Common browsers:

- Google Chrome
- Microsoft Edge
- Mozilla Firefox

Open Developer Tools:

```text
F12
```

or

```text
Right Click -> Inspect
```

Production Support Use Cases:

- Identifying failed API calls
- Locating 404 and 500 errors
- Reviewing authentication issues
- Investigating page performance problems

---

## curl

`curl` is a command-line utility used to send HTTP and HTTPS requests.

It is one of the most commonly used tools for validating application availability and testing APIs.

### Basic Request

```bash
curl https://orders.company.com
```

Returns the response from the server.

---

### View HTTP Headers

```bash
curl -I https://orders.company.com
```

Sample output:

```http
HTTP/1.1 200 OK
Content-Type: text/html
Server: nginx
```

Useful for:

- Confirming server availability
- Identifying status codes
- Reviewing response headers

---

### View Detailed Connection Information

```bash
curl -v https://orders.company.com
```

Displays:

- DNS resolution details
- SSL/TLS negotiation
- Request headers
- Response headers

Useful during advanced troubleshooting.

---

### Testing REST APIs

Example:

```bash
curl https://api.company.com/customers
```

Response:

```json
{
  "customerId": 100,
  "name": "Jane Smith"
}
```

Production Support Use Cases:

- Verify API availability
- Test endpoints
- Confirm authentication behavior
- Validate application responses

---

## Postman

Postman is a popular API testing tool used by developers, QA teams, and Production Support analysts.

Capabilities include:

- Sending HTTP requests
- Testing REST APIs
- Managing authentication tokens
- Viewing response data
- Automating API tests

Example Request:

```http
GET https://api.company.com/customers
```

Benefits:

- User-friendly interface
- No command-line experience required
- Easy API troubleshooting

Production Support Use Cases:

- Reproducing application issues
- Verifying backend services
- Testing integrations

---

## Fiddler

Fiddler is a web debugging proxy that captures HTTP and HTTPS traffic.

Capabilities include:

- Monitoring requests
- Inspecting responses
- Viewing headers
- Analyzing redirects
- Troubleshooting authentication failures

Production Support Use Cases:

- Troubleshooting web applications
- Investigating API communications
- Diagnosing security-related issues

---

The Network tab within Developer Tools is often one of the fastest ways to diagnose web application problems.

Information available includes:

- Request URLs
- Response times
- Status codes
- Payloads
- Redirects
- Authentication failures

Example:

```text
Request:
GET /customers

Response:
```

## Common Troubleshooting Workflow

When investigating a web application issue:

### Step 1

Verify DNS resolution.

```bash
nslookup orders.company.com
```

### Step 2

Test network connectivity.

```bash
ping orders.company.com
```

### Step 3

Validate the HTTP response.

```bash
curl -I https://orders.company.com
```

### Step 4

Review HTTP status codes.

```text
200
404
500
503
```

### Step 5

Examine server and application logs.

### Step 6

Identify and resolve the root cause.

## Production Support Example

### Incident

Users report that the Order Management System is unavailable.

### Investigation

DNS Test:

```bash
nslookup orders.company.com
```

Result:

```text
Successful
```

Connection Test:

```bash
curl -I https://orders.company.com
```

Response:

```http
HTTP/1.1 503 Service Unavailable
```

Application Logs:

```text
Backend service offline
```

### Root Cause

A dependent application service was unavailable.

### Resolution

Restart the affected service.

### Lesson Learned

Simple tools such as `curl` can quickly identify whether an issue is related to connectivity, application availability, or backend services.
