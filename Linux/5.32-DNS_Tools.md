# DNS Troubleshooting with `nslookup` and `dig`

## Learning Objectives

By the end of this lesson, students will be able to:

* Explain why DNS tools are used in network troubleshooting.
* Query DNS records with `nslookup`.
* Query DNS records with `dig`.
* Use forward and reverse DNS lookups.
* Select DNS record types such as A, AAAA, MX, CNAME, NS, and TXT.
* Compare DNS results from the system resolver and a specific DNS server.

---

## What Is DNS?

The Domain Name System, or DNS, translates names such as `example.com`
into IP addresses and stores other information used by network services.

DNS troubleshooting is useful when:

* A website does not resolve.
* A hostname resolves to an unexpected IP address.
* An email server cannot be found.
* A service should have a new DNS record.
* An application receives `NXDOMAIN`, `SERVFAIL`, or timeout errors.

The most common DNS record types include:

| Record | Purpose |
| --- | --- |
| `A` | Maps a hostname to an IPv4 address |
| `AAAA` | Maps a hostname to an IPv6 address |
| `CNAME` | Defines an alias to another name |
| `MX` | Identifies mail servers |
| `NS` | Identifies authoritative name servers |
| `TXT` | Stores text used for verification, policies, or other metadata |
| `PTR` | Maps an IP address to a hostname |

## Using `nslookup`

`nslookup` is available on many Linux distributions, as well as Windows and
macOS. It performs basic forward and reverse DNS lookups.

### Basic forward lookup

```bash
nslookup example.com
```

The output identifies the DNS server used and the IP address returned.

### Query an IPv6 address

```bash
nslookup -type=AAAA example.com
```

### Query a specific record type

```bash
nslookup -type=MX example.com
nslookup -type=NS example.com
nslookup -type=TXT example.com
nslookup -type=CNAME www.example.com
```

### Query a specific DNS server

The basic syntax is:

```bash
nslookup hostname DNS_SERVER
```

For example:

```bash
nslookup example.com 8.8.8.8
```

Using a specific server helps determine whether the problem comes from a
configured resolver, a DNS cache, or the public DNS record.

### Reverse lookup

```bash
nslookup 93.184.216.34
```

A reverse lookup asks which hostname is associated with an IP address.

### Interactive mode

Start interactive mode with:

```bash
nslookup
```

Then enter commands such as:

```text
> set type=A
> example.com
> set type=MX
> example.com
> exit
```

## Using `dig`

`dig`, short for Domain Information Groper, provides detailed DNS query
output. It is available on systems that include the `dnsutils`, `bind-utils`,
or `bind-tools` package.

### Basic lookup

```bash
dig example.com
```

The output is divided into sections:

* Header: DNS status and query flags
* Question: the name and record type queried
* Answer: returned DNS records
* Authority: servers authoritative for the queried zone
* Additional: extra records such as server addresses

### Query a record type

```bash
dig example.com A
dig example.com AAAA
dig example.com MX
dig example.com NS
dig example.com TXT
dig example.com CNAME
```

### Print only the answer

```bash
dig example.com +short
```

This is useful for scripts and quick checks:

```bash
dig google.com A +short
```

You can include multiple record queries:

```bash
dig example.com A +short
dig example.com AAAA +short
dig example.com MX +short
```

### Query a specific DNS server

Use `@` followed by the server address:

```bash
dig @8.8.8.8 example.com A
dig @1.1.1.1 example.com MX
```

### Reverse DNS lookup

Use the IP address with `-x`:

```bash
dig -x 93.184.216.34
```

### Trace the DNS lookup path

```bash
dig example.com +trace
```

`+trace` displays the DNS delegation path from root servers to the
authoritative servers.

### Check DNS response time

```bash
dig example.com
```

The `Query time` line near the bottom of the output shows how long the DNS
server took to answer.

## Comparing Output from `nslookup` and `dig`

| Task | `nslookup` | `dig` |
| --- | --- | --- |
| Basic lookup | `nslookup example.com` | `dig example.com` |
| Query A record | `nslookup -type=A example.com` | `dig example.com A` |
| Query MX records | `nslookup -type=MX example.com` | `dig example.com MX` |
| Use a server | `nslookup example.com 8.8.8.8` | `dig @8.8.8.8 example.com` |
| Reverse lookup | `nslookup 93.184.216.34` | `dig -x 93.184.216.34` |
| Short answer | `nslookup` does not offer this as directly | `dig +short` |

`nslookup` is useful for quick interactive queries. `dig` provides more
detail and is preferred when scripting or diagnosing DNS behavior.

## Interpreting Common Results

| Result or status | Meaning |
| --- | --- |
| `NOERROR` | Query succeeded; an answer may or may not be present |
| `NXDOMAIN` | The queried name does not exist |
| `SERVFAIL` | The DNS server failed to complete the request |
| `REFUSED` | The DNS server refused the query |
| `ANSWER: 0` | The name exists but no records of the queried type were returned |
| `timed out` | The resolver did not receive a response in time |

An empty answer does not always mean the name does not exist. For example,
the domain may have an A record but no MX record.

## Basic Troubleshooting Workflow

1. Query the hostname using the system resolver:

   ```bash
   dig example.com A +short
   ```

2. Query a known public resolver:

   ```bash
   dig @8.8.8.8 example.com A +short
   ```

3. If the answers differ, investigate local DNS configuration, caches, or
   firewall rules.

4. Check the authoritative name servers:

   ```bash
   dig example.com NS +short
   ```

5. Query an authoritative server directly:

   ```bash
   dig @NS_SERVER example.com A
   ```

6. Trace the delegation path:

   ```bash
   dig example.com +trace
   ```

## Practice Exercises

1. Look up `example.com` with `nslookup`.

   ```bash
   nslookup example.com
   ```

2. Look up the same name with `dig`.

   ```bash
   dig example.com A
   ```

3. Display only the IPv4 answer.

   ```bash
   dig example.com A +short
   ```

4. Display the IPv6 address records.

   ```bash
   dig example.com AAAA +short
   ```

5. Find the authoritative name servers.

   ```bash
   dig example.com NS +short
   ```

6. Find the mail servers.

   ```bash
   dig example.com MX
   ```

7. Query `example.com` through Google's public DNS resolver.

   ```bash
   dig @8.8.8.8 example.com A
   ```

8. Perform a reverse lookup for `93.184.216.34`.

   ```bash
   dig -x 93.184.216.34
   ```

9. Trace DNS resolution for `example.com`.

   ```bash
   dig example.com +trace
   ```

10. Start `nslookup` in interactive mode and query the MX record for
    `example.com`.

    ```text
    nslookup
    > set type=MX
    > example.com
    > exit
    ```

## Key Takeaways

* `nslookup` is useful for quick interactive DNS queries.
* `dig` provides detailed output and is useful for scripting and advanced
  troubleshooting.
* Use record types to request the desired DNS information.
* Querying a specific DNS server helps isolate resolver problems.
* Use `+short` in `dig` for concise script-friendly results.
* Reverse lookups use `nslookup IP_ADDRESS` or `dig -x IP_ADDRESS`.
