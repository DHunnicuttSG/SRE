# Introduction

Modern applications must support:

- Large numbers of users
- High transaction volumes
- Continuous availability
- Scalability
- Fault tolerance

A single server often cannot handle all incoming traffic.

To solve this problem, organizations use load balancers.

A load balancer distributes incoming requests across multiple servers to prevent any single server from becoming overloaded.

Without load balancing:

```text
All Users
    |
    v
Single Server
```

If that server fails:

```text
Application Outage
```

With load balancing:

```text
Users
   |
Load Balancer
   |
+-----+-----+-----+
|     |     |     |
v     v     v     v

Server1 Server2 Server3
```

Traffic is distributed across multiple systems.

---

# What Is a Load Balancer?

A load balancer is a device or service that distributes network traffic among multiple servers.

Its primary goals are:

- Improve availability
- Improve performance
- Increase scalability
- Prevent server overload

Think of a load balancer as a traffic officer directing vehicles to multiple lanes rather than allowing all traffic into a single lane.

---

# Why Load Balancers Matter

Consider an online shopping application.

During normal operation:

```text
100 Users
```

A single server may be sufficient.

During a holiday sale:

```text
10,000 Users
```

A single server may become overwhelmed.

A load balancer distributes traffic across multiple servers to handle increased demand.

# Basic Load Balancing Architecture

```text

   |
   v
Load Balancer
   |
+-----+-----+-----+
|     |     |     |
v     v     v     v

Web1  Web2  Web3
```

Users connect only to the load balancer.

The load balancer determines which server should handle the request.

# Benefits of Load Balancing

## High Availability

If one server fails:

```text
Server 1 = Down
Server 2 = Healthy
Server 3 = Healthy
```

Traffic is automatically redirected to healthy servers.

Users may never notice the failure.

---

## Scalability

Additional servers can be added as demand grows.

Example:

```text
Web1
Web2
Web3
Web4
Web5
```

Traffic is distributed across all available systems.

---

## Improved Performance

Server workloads are distributed evenly.

This helps reduce:

- Response times
- Resource bottlenecks
- Server overload

---

## Fault Tolerance

The application continues functioning even if individual servers fail.

# Load Balancer Placement

A load balancer typically sits between users and application servers.

Example:

```text
Users
  |
Internet
  |
Load Balancer
  |
+-----+-----+
|           |
v           v

Web1      Web2
```

All traffic passes through the load balancer first.

---

# How Load Balancing Works

When a request arrives:

```text
User Request
      |
      v
Load Balancer
```

The load balancer decides which server will handle the request.

Example:

```text
Request 1 -> Server 1
Request 2 -> Server 2
Request 3 -> Server 3
```

The user remains unaware of which server actually processes the request.

---

# Common Load Balancing Algorithms

The load balancer uses algorithms to determine traffic distribution.

---

# Round Robin

Traffic is distributed evenly in sequence.

Example:

```text
Request 1 -> Server 1
Request 2 -> Server 2
Request 3 -> Server 3
Request 4 -> Server 1
Request 5 -> Server 2
```

Advantages:

- Simple
- Easy to implement

---

# Least Connections

Traffic is sent to the server with the fewest active connections.

Example:

```text
Server 1 = 100 Connections
Server 2 = 20 Connections

New Request -> Server 2
```

Advantages:

- Better workload balancing
- Handles uneven traffic more effectively

---

# Weighted Round Robin

Servers receive traffic based on assigned weights.

Example:

```text
Server 1 Weight = 3
Server 2 Weight = 1
```

Traffic distribution:

```text
Server 1 receives 75%
Server 2 receives 25%
```

Useful when servers have different capacities.

---

# Health Checks

One of the most important load balancer functions is monitoring server health.

Health checks verify whether servers can process requests successfully.

---

## Health Check Example

The load balancer periodically checks:

```text
https://server01/health
```

Expected Response:

```text
200 OK
```

If the health check fails:

```text
Server marked unhealthy
```

Traffic is redirected elsewhere.

---

# Healthy vs Unhealthy Servers

Example:

```text
Server 1 -> Healthy
Server 2 -> Healthy
Server 3 -> Unhealthy
```

Traffic distribution:

```text
Server 1 -> Receives Traffic
Server 2 -> Receives Traffic
Server 3 -> Removed
```

This helps maintain availability.

---

# Session Persistence (Sticky Sessions)

Some applications require user sessions to remain on a specific server.

Example:

```text
Login Session Created
```

If subsequent requests are directed to another server:

```text
Session Lost
```

Users may be logged out unexpectedly.

Session persistence keeps a user connected to the same backend server.

---

# Layer 4 vs Layer 7 Load Balancing

## Layer 4 Load Balancing

Operates using:

```text
IP Addresses
TCP Ports
```

Example:

```text
IP: 10.10.10.20
Port: 443
```

Advantages:

- Fast
- Efficient
- Lower overhead

---

## Layer 7 Load Balancing

Operates at the application layer.

Can examine:

```text
URLs
HTTP Headers
Cookies
Hostnames
```

Example:

```text
/api/*  -> API Servers

/images/* -> Image Servers
```

Advantages:

- Intelligent routing
- Better traffic management

# Common Production Support Incidents

## Failed Health Checks

### Symptoms

```text
Application Unavailable
```

### Cause

Load balancer believes all servers are unhealthy.

### Impact

No traffic reaches application servers.

---

## Incorrect Routing Rules

### Symptoms

```text
Users Receive Errors
```

### Cause

Load balancer routes traffic incorrectly.

---

## Session Persistence Issues

### Symptoms

```text
User Randomly Logged Out
```

### Cause

Requests are routed to different servers.

---

## Backend Server Failure

### Symptoms

```text
Intermittent Errors
```

### Cause

One server is unhealthy.

Some requests succeed while others fail.

---

## SSL Certificate Issues

### Symptoms

```text
HTTPS Failure
Certificate Errors
```

### Cause

Certificate expired or installed incorrectly on the load balancer.

# Production Support Case Study

## Incident

Users report:

```text
Customer Portal Unavailable
```

---

## Investigation

DNS:

```text
Successful
```

Server Connectivity:

```text
Successful
```

Application Servers:

```text
Running
```

Health Checks:

```text
Failing
```

---

## Findings

Health check URL changed during deployment:

```text
/health
```

to:

```text
/status
```

Load balancer still checked:

```text
/health
```

All servers marked unhealthy.

---

## Root Cause

Health check configuration mismatch.

---

## Resolution

Update health check path.

Servers marked healthy.

Traffic restored.

---

## Lesson Learned

Small configuration changes can cause major outages when load balancer health checks are affected.

# Key Takeaways

- Load balancers distribute traffic across multiple servers.
- Load balancing improves scalability, performance, and availability.
- Health checks determine server availability.
- Load balancers automatically remove unhealthy servers from traffic rotation.
- Session persistence helps maintain user sessions.
- Layer 4 and Layer 7 load balancers operate differently.
- Load balancer issues are a common source of application outages.
- Understanding load balancing helps Production Support teams troubleshoot incidents more effectively.
