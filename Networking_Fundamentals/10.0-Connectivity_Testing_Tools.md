# Connectivity Testing Tools

## Learning Objectives

By the end of this lesson, students will be able to:

- Explain the purpose of network connectivity testing.
- Use common connectivity testing tools in Windows and Linux.
- Verify DNS resolution, IP connectivity, and port accessibility.
- Interpret common troubleshooting results.
- Identify network, server, firewall, and application-related issues.
- Apply a structured troubleshooting methodology during incident investigations.
- Use connectivity testing tools to support root cause analysis.

---

# Introduction

One of the first responsibilities of a Production Support analyst is determining whether systems can communicate with each other.

Users may report:

```text
The application is down.
```

```text
I can't log in.
```

```text
The website won't load.
```

```text
The database connection failed.
```

Before investigating application code, support teams should confirm that communication between systems is working correctly.

Connectivity testing tools help analysts answer questions such as:

- Can the server be reached?
- Does DNS resolve correctly?
- Is the required port open?
- Is traffic being blocked?
- Is the application responding?

These tools often allow analysts to identify problems within minutes.

---

# The Connectivity Testing Process

A common troubleshooting approach is:

```text
1. Verify DNS Resolution
2. Verify Network Connectivity
3. Verify Port Accessibility
4. Verify Application Response
5. Review Logs
6. Determine Root Cause
```

This process helps isolate failures quickly and efficiently.

# Ping

## Purpose

Ping verifies basic IP connectivity between systems.

It uses the Internet Control Message Protocol (ICMP).

---

## Windows

```cmd
ping server01
```

---

## Linux

```bash
ping server01
```

---

## Example Output

```text
Reply from 10.10.5.25:
Bytes=32 Time=12ms TTL=128
```

---

## What Ping Can Tell You

Successful ping indicates:

- Host is reachable
- IP communication exists
- Routing is functioning

Failed ping may indicate:

- Device offline
- Network issue
- Firewall restrictions
- Incorrect IP address

---

## Production Support Example

User reports:

```text
Cannot access application.
```

Ping results:

```text
Request Timed Out
```

Possible causes:

- Server offline
- Firewall block
- Network outage

---

# Traceroute / Tracert

## Purpose

Traceroute identifies the network path between two systems.

It shows each device (hop) the traffic passes through.

---

## Windows

```cmd
tracert server01
```

---

## Linux

```bash
traceroute server01
```

---

## Example Output

```text
1   192.168.1.1
2   10.10.5.1
3   10.20.10.5
4   10.20.10.25
```

---

## What Traceroute Can Tell You

- Routing paths
- Communication delays
- Network hops
- Potential routing failures

---

## Production Support Example

Users in one office cannot access an application.

Traceroute reveals:

```text
Traffic stops at Router 3
```

Possible cause:

```text
Routing issue
```

---

# Nslookup

## Purpose

Checks DNS resolution.

Determines whether a hostname resolves to an IP address.

---

## Windows

```cmd
nslookup orders.company.com
```

---

## Linux

```bash
nslookup orders.company.com
```

---

## Example Output

```text
Name: orders.company.com

Address: 10.20.30.40
```

---

## What Nslookup Can Tell You

- DNS is functioning
- Hostname exists
- Correct IP address is returned

---

## Production Support Example

Users report:

```text
Application unavailable
```

Nslookup returns:

```text
Non-existent domain
```

Possible cause:

```text
Missing DNS record
```

---

# Dig

## Purpose

Provides detailed DNS information.

Commonly used in Linux environments.

---

## Example

```bash
dig orders.company.com
```

---

## Information Provided

- DNS records
- TTL values
- Name servers
- Resolution details

---

## Production Support Example

After a deployment:

```text
Users still reach the old server.
```

Dig reveals:

```text
DNS cache still active
```

TTL analysis explains the delay.

---

# Ipconfig

## Purpose

Displays local network configuration on Windows systems.

---

## Command

```cmd
ipconfig
```

---

## Common Information

```text
IPv4 Address
Subnet Mask
Default Gateway
```

---

## View Detailed Information

```cmd
ipconfig /all
```

---

## Clear DNS Cache

```cmd
ipconfig /flushdns
```

---

## Production Support Use Cases

- Verify device IP address
- Verify DNS servers
- Troubleshoot DNS issues
- Validate gateway configuration

---

# Netstat

## Purpose

Displays active connections and listening ports.

---

## Windows

```cmd
netstat -ano
```

---

## Linux

```bash
netstat -an
```

---

## Example Output

```text
TCP 0.0.0.0:443 LISTENING
```

---

## What Netstat Can Tell You

- Active connections
- Listening services
- Open ports
- Process associations

---

## Production Support Example

Application unavailable.

Netstat shows:

```text
Port 443 not listening
```

Root cause:

```text
Web service stopped
```

---

# SS

## Purpose

Modern Linux replacement for Netstat.

---

## Command

```bash
ss -tuln
```

---

## Parameters

```text
-t  TCP
-u  UDP
-l  Listening Ports
-n  Numeric Output
```

---

## Use Cases

- Viewing open ports
- Identifying services
- Connection troubleshooting

---

# Telnet

## Purpose

Tests TCP connectivity to a specific port.

---

## Example

```bash
telnet server01 443
```

---

## Successful Connection

```text
Connected to server01
```

---

## Failed Connection

```text
Connection Refused
```

or

```text
Unable to Connect
```

---

## Production Support Example

Database issue reported.

Test:

```bash
telnet dbserver 1433
```

Result:

```text
Connection Failed
```

Possible causes:

- Firewall issue
- Service unavailable
- Incorrect port

---

# PowerShell Test-NetConnection

## Purpose

A modern Windows tool for testing connectivity.

---

## Example

```powershell
Test-NetConnection server01 -Port 443
```

---

## Information Provided

- DNS resolution
- Port accessibility
- Network route
- Connectivity status

---

## Production Support Benefits

Single command provides multiple troubleshooting results.

---

# Curl

## Purpose

Tests HTTP and HTTPS connectivity.

---

## Example

```bash
curl https://orders.company.com
```

---

## View Headers

```bash
curl -I https://orders.company.com
```

---

## View Detailed Information

```bash
curl -v https://orders.company.com
```

---

## Production Support Use Cases

- Verify web applications
- Test APIs
- Validate HTTPS connectivity
- Troubleshoot certificates

# Common Connectivity Testing Workflow

## Step 1: Verify DNS

```bash
nslookup orders.company.com
```

Expected Result:

```text
IP Address Returned
```

---

## Step 2: Verify Reachability

```bash
ping orders.company.com
```

Expected Result:

```text
Reply Received
```

---

## Step 3: Verify Port Access

```powershell
Test-NetConnection orders.company.com -Port 443
```

Expected Result:

```text
TcpTestSucceeded : True
```

---

## Step 4: Verify Application Response

```bash
curl -I https://orders.company.com
```

Expected Result:

```http
HTTP/1.1 200 OK
```

---

## Step 5: Review Application Logs

If all connectivity tests succeed, investigate the application itself.

# Production Support Case Study

## Incident

Users report:

```text
Order Application Unavailable
```

---

## Investigation

DNS:

```text
Successful
```

Ping:

```text
Successful
```

Port 443:

```text
Failed
```

Netstat:

```text
Port 443 Not Listening
```

---

## Root Cause

Web service stopped unexpectedly.

---

## Resolution

Restart service.

Verify port availability.

Confirm application access.

---

## Lesson Learned

Connectivity testing narrowed the investigation from an entire application stack to a single service.

# Tool Selection Guide

| Problem | Recommended Tool |
|----------|----------|
| DNS Resolution | nslookup, dig |
| Network Reachability | ping |
| Routing Issues | tracert, traceroute |
| Local Configuration | ipconfig, ip addr |
| Open Ports | netstat, ss |
| Port Testing | telnet, Test-NetConnection |
| Web/API Testing | curl |
| DNS Cache Issues | ipconfig /flushdns |

# Key Takeaways

- Connectivity testing tools are among the most important resources available to Production Support teams.
- Ping validates basic IP connectivity.
- Traceroute identifies routing paths.
- Nslookup and Dig troubleshoot DNS issues.
- Netstat and SS identify listening services and connections.
- Telnet and Test-NetConnection verify port accessibility.
- Curl validates web application and API connectivity.
- A structured troubleshooting process reduces Mean Time to Resolution (MTTR).

Connectivity testing tools provide the foundation for effective Production Support troubleshooting.
