# Git Workflow Exercises: Instructor Key

This key describes the expected workflow and concepts. Repository URLs, default branch names, commit IDs, and output details depend on the class repository.

## Exercise 1: Clone and Inspect

Example:

```bash
git clone <repository-url>
cd <repository-folder>
git status
git remote -v
git log --oneline -5
```

Expected concepts:

- `git clone` creates a local repository with working files and history.
- The default remote name is `origin`.
- A fresh clone normally starts on the remote repository's default branch with a clean working tree.
- The exact branch and commit depend on the training repository.

## Exercise 2: Make and Commit a Change

Example:

```bash
git switch -c docs/student-first-change

# Edit the README.
git status
git diff
git add README.md
git diff --staged
git commit -m "Add student setup note"
git log --oneline -3
git status
```

Expected concepts:

- The branch name should follow the class convention.
- `git add` stages the selected file; `git diff --staged` confirms the commit contents.
- After commit, the working tree can be clean while the commit remains only in the local repository.
- A commit is not visible on GitHub until it is pushed.

## Exercise 3: Push a Topic Branch

Example:

```bash
git push -u origin docs/student-first-change
```

Expected concepts:

- The branch is published to the remote, assuming permission and connectivity.
- `-u` sets the upstream tracking branch so later `git push` and `git pull` can infer the remote branch.
- A pull request proposes the branch for review and integration; pushing alone does not merge it.

## Exercise 4: Fetch, Inspect, and Pull

On the student's default branch:

```bash
git status -sb
git fetch origin
git status -sb
git log --oneline HEAD..origin/main
git pull --ff-only origin main
git status -sb
```

Replace `main` if the training repository uses another default branch.

Expected concepts:

- Fetch updates remote-tracking information such as `origin/main`; it does not modify the current branch's working files.
- The log comparison shows commits reachable from `origin/main` but not from the student's current `HEAD`.
- Pull fetches and integrates the selected remote branch. With `--ff-only`, it refuses to integrate if a fast-forward is not possible.
- If there is no new remote commit, fetch/pull may produce no visible content change.
- Uncommitted changes should be addressed before switching or pulling.

## Exercise 5: Review and Safe Cleanup

Expected concepts:

- `.gitignore` prevents matching untracked files from being added accidentally; it does not remove a file already tracked.
- `git restore --staged <file>` removes the file from the staging area while keeping working-tree edits.
- `git restore <file>` replaces unstaged working-tree content with the indexed version and can discard edits.
- Credentials should never be committed. If exposed, they must be rotated/revoked; a later deletion does not erase prior history.

## Optional Challenge: Resolve a Conflict

Expected process:

```bash
git status
# Edit the conflicted file and remove conflict markers.
git diff
git add <resolved-file>
```

Then complete the merge using the class repository's workflow. Students should explain which content was retained and why. Do not use force-push to erase another learner's work.
