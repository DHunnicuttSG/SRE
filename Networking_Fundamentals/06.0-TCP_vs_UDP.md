# Introduction

One of the most important concepts in networking is understanding how data moves between systems.

At the Transport Layer (Layer 4 of the OSI Model), two primary protocols are responsible for moving data across networks:

- TCP (Transmission Control Protocol)
- UDP (User Datagram Protocol)

Both protocols serve the same fundamental purpose:

> Deliver data from one system to another.

However, they achieve this goal in very different ways.

Understanding when TCP or UDP is being used can help Production Support professionals diagnose connectivity problems, performance issues, application failures, and timeout errors.

---

# The Role of the Transport Layer

The Transport Layer is responsible for:

- End-to-end communication
- Data delivery
- Error detection
- Connection management
- Data sequencing

Think of the Transport Layer as a delivery service.

Its job is to ensure that information gets from the sender to the correct application on the receiving system.

---

# What Is TCP?

TCP (Transmission Control Protocol) is a connection-oriented protocol that provides reliable communication between devices.

TCP is designed to ensure that data arrives:

- Completely
- In the correct order
- Without duplication
- Without corruption

Because reliability is its primary goal, TCP performs several validation and verification processes during communication.

---

# Key Characteristics of TCP

TCP provides:

## Reliability

The receiving system acknowledges received data.

If data is lost, TCP retransmits it.

---

## Ordered Delivery

Data arrives in the same order it was sent.

Example:

```text
Message Sent:

Packet 1
Packet 2
Packet 3

Message Received:

Packet 1
Packet 2
Packet 3
```

Order is preserved.

---

## Error Checking

TCP verifies that data arrives correctly.

Corrupted packets are retransmitted.

---

## Flow Control

TCP prevents faster systems from overwhelming slower systems.

This helps maintain stable communication.

---

## Connection-Oriented Communication

TCP establishes a connection before transmitting data.

Both endpoints must agree to communicate before data transfer begins.

---

# The TCP Three-Way Handshake

Before communication begins, TCP establishes a connection through a process called the Three-Way Handshake.

### Step 1: SYN

The client requests a connection.

```text
Client -> Server

SYN
```

Meaning:

```text
Can we communicate?
```

---

### Step 2: SYN-ACK

The server responds.

```text
Server -> Client

SYN-ACK
```

Meaning:

```text
Yes, I received your request.
Can you hear me?
```

---

### Step 3: ACK

The client confirms.

```text
Client -> Server

ACK
```

Meaning:

```text
Connection established.
```

---

# TCP Handshake Diagram

```text
Client                    Server

  SYN   ----------------->

        <----------------- SYN-ACK

  ACK   ----------------->

        Connection Established
```

After the handshake completes, data transmission begins.

# What Is UDP?

UDP (User Datagram Protocol) is a connectionless protocol designed for speed and efficiency.

Unlike TCP, UDP does not establish a connection before transmitting data.

UDP simply sends information without verifying delivery.

---

# Key Characteristics of UDP

UDP provides:

## Fast Communication

Data is sent immediately.

No connection setup is required.

---

## Low Overhead

UDP uses fewer resources because it performs less validation.

---

## No Guaranteed Delivery

Packets may be lost.

UDP does not attempt retransmission.

---

## No Packet Ordering

Packets may arrive out of order.

The receiving application must handle this if necessary.

---

## Connectionless Communication

No handshake occurs before data exchange.

Data is simply transmitted.

---

# UDP Communication Example

```text
Client -> Server

Data Sent
```

There is no:

```text
SYN
SYN-ACK
ACK
```

UDP immediately sends traffic.

This approach improves speed but sacrifices reliability.

---

# Common UDP Applications

UDP is often used when speed is more important than perfect accuracy.

Examples include:

| Service | Port |
|----------|----------|
| DNS | 53 |
| DHCP | 67/68 |
| NTP | 123 |
| SNMP | 161 |
| VoIP | Various |
| Video Streaming | Various |
| Online Gaming | Various |

These applications can tolerate occasional packet loss.

---

# TCP vs UDP Comparison

## Reliability

### TCP

```text
Reliable
```

Guaranteed delivery.

### UDP

```text
Best Effort
```

No delivery guarantees.

---

## Connection Setup

### TCP

Requires connection establishment.

```text
Three-Way Handshake
```

### UDP

No connection setup required.

---

## Speed

### TCP

Slower due to validation and error checking.

### UDP

Faster because it minimizes processing overhead.

---

## Packet Ordering

### TCP

Packets arrive in order.

### UDP

Packets may arrive out of order.

---

## Error Recovery

### TCP

Retransmits lost data.

### UDP

Does not retransmit lost data.

# Real-World Analogy

Imagine sending a package through the mail.

## TCP

Certified mail with signature confirmation.

```text
Package Sent
Package Tracked
Delivery Confirmed
```

Reliable but slower.

---

## UDP

Dropping flyers into mailboxes.

```text
Flyers Sent
No Confirmation
```

Fast but not guaranteed.

# Why Web Applications Use TCP

When a user submits an online order:

```text
Purchase Amount:
$2,500
```

The system cannot risk losing information.

Requirements:

- Accuracy
- Reliability
- Confirmation

Therefore, applications use TCP.

Examples:

```text
E-Commerce
Banking
Healthcare Systems
Database Transactions
```

---

# Why DNS Often Uses UDP

DNS requests are typically very small.

Example:

```text
What is the IP address for:

orders.company.com?
```

The response is usually small enough to fit inside a single UDP packet.

Benefits:

- Faster processing
- Lower overhead
- Reduced latency

This makes UDP ideal for DNS lookups.

# Common Commands for TCP/UDP Troubleshooting

## Netstat

Displays active connections and listening services.

```bash
netstat -an
```

---

## ss

Modern Linux utility for viewing sockets.

```bash
ss -tuln
```

Where:

```text
-t = TCP
-u = UDP
-l = Listening
-n = Numeric output
```

---

## Test-NetConnection

Windows connectivity testing.

```powershell
Test-NetConnection server01 -Port 443
```

Useful for TCP testing.

---

## Telnet

Tests TCP connectivity.

```bash
telnet server01 443
```

---

## Tcpdump

Captures network packets.

```bash
tcpdump -i eth0
```

Useful for advanced investigation.

# Summary

TCP and UDP are the foundation of Transport Layer communication. Although both protocols move data between systems, they are designed for different purposes.

TCP prioritizes reliability and is commonly used by applications where data accuracy is critical, including web applications, APIs, databases, and financial systems.

UDP prioritizes speed and efficiency and is commonly used for DNS, streaming, VoIP, and monitoring traffic.

Production Support professionals should understand the characteristics, strengths, and limitations of both protocols so they can quickly recognize communication failures, identify root causes, and restore services with minimal business impact.
